## Zone Seed Requirements

Use a small, sensible set of development zones for the Dhaka Tesla pooling application.

Each zone must satisfy the existing Prisma model:

```prisma
model Zone {
  id        String   @id @default(uuid()) @db.Uuid
  name      String   @unique @db.VarChar(50)
  type      ZoneType
  latitude  Decimal  @db.Decimal(9, 6)
  longitude Decimal  @db.Decimal(9, 6)
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")
}
```

Use the existing `ZoneType` enum:

```text
AREA
POINT
```

Choose a small number of useful development zones rather than creating a large dataset.

## Seed Design

The seed must be:

* idempotent
* deterministic
* simple
* readable
* safe to run repeatedly
* free of destructive deletes
* free of unnecessary dependencies
* consistent with the project's existing TypeScript/ESM style

Use `upsert` based on the unique `name` field so repeated runs update the existing zone rather than creating duplicates.

Do not use:

* `deleteMany`
* database resets
* random data
* generated fake data
* hardcoded UUIDs unless there is a genuine reason
* unnecessary seed frameworks

## Database Access

Reuse the project's existing Prisma database configuration if appropriate rather than creating a second database connection architecture.

The existing database module is:

```text
src/config/database.ts
```

Follow the project's existing Prisma 7 PostgreSQL adapter setup.

Make sure the seed properly finishes and disconnects from Prisma after execution.

Use proper error handling so a failed seed exits with a non-zero status.

## Decimal Handling

Because `latitude` and `longitude` are Prisma `Decimal` fields, use a type-safe approach compatible with the existing generated Prisma client.

Do not weaken TypeScript types with `any`.
